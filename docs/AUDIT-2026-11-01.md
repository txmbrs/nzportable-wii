# Review of post-r27 performance and cooperation-r18az changes

Reviewed 2026-11-01. Production code was read only. Diagnostic probes were
written under build/audit-20261101; this report is not a new game release.
Compared working sources with the separate publication checkout at f169767.
Read all three supplied reports and checked their claims against local code.
No Wii execution, new release build, or PC-to-Wii network session was performed.

## Confirmed defects / incomplete fixes

### P1: Blind reliable retransmission can execute a signon command twice

engine/common/net_chan.c:884-897 (under fte-online/fteqw-master).

The added retry resends reliable payload without proof the previous payload was
lost. The receiver at lines 1433-1447 accepts a newer sequence and toggles its
incoming reliable bit whenever reliable_message is present. If the first payload
arrives but its ACK is lost/delayed, the retry has a newer packet sequence and
is processed again. This can duplicate commands and toggle the receiver ACK out
of agreement with the sender. This is different from retrying the same packet
sequence or using a transport with message IDs and duplicate suppression.

The function-static retry timestamp is shared by channels and is not set on
the initial reliable send. With first send at 1000 ms and next call at 1016 ms,
the first forced retry already passes the 400 ms check (timestamp starts at 0).
Thus it does not even guarantee 400 ms from the previous reliable transmission.

Evidence: build/audit-20261101/retry.c extracts the actual added conditional and
models the existing receiver toggle rule. Host execution reproduces duplicate
delivery and ACK disagreement. This is a protocol counterexample, not a full
FTE integration test or proof it caused a particular recorded Wii timeout.

Action: replace blind resending with a protocol-correct loss/ACK strategy.
Test lost request, delivered request with lost ACK, delayed ACK, reordering,
and reconnect. A per-channel timer alone does not solve duplicate delivery.

### P1: Alleged image allocation safeguard cannot handle allocation failure

engine/client/image.c:8535-8583 checks NULL after BZ_Malloc. But
engine/common/zone.c:501-516 calls Sys_Error when BZF_Malloc fails, before
returning. The new NULL branches cannot recover this out-of-memory path.
There is no basis for claiming the menu allocation crash has been fixed.

Action: fix resource lifetime/fragmentation and budget first. If a recoverable
allocation is intended, use a fallible allocator and audit all callers for a
NULL result and consistent cleanup; blindly replacing BZ_Malloc is insufficient.

### P2: New lighting-cache hash invokes signed integer overflow

source/render/r_light.c:281-283 multiplies signed int coordinates before casting
the result to unsigned. At x=1000 the expression 1000 * 73856093 overflows int.
The outer unsigned cast is too late to make that multiplication defined.

Evidence: build/audit-20261101/light_hash.c extracts the actual expression;
UBSan reports signed integer overflow and terminates as configured.
Action: perform multiplication in an unsigned type, and explicitly define
cache invalidation for map reload and changes to lightstyle values. The hash
failure is confirmed; visible corruption on Wii was not measured.

### P2: Performance changes reduce animation/effect fidelity

source/platform/sdl/gl/gl_rmain.c:689 rounds every interpolation blend to steps
of 1/8. These are no longer the same interpolated vertices as before; small
motion steps can become visible. The modification is not guarded by PLATFORM_WII.

source/render/r_particles.c:1173,1259,1295 caps particle-generated decals at two
per update. Additional blood/burn marks are discarded, not queued or batched.
This also applies outside Wii. These changes contradict a blanket claim of
unchanged visual quality. They do not establish a cause for location-specific
frame drops on NDU or Warehouse.

Action: retain exact interpolation/effects for the default path or explicitly
expose and document a quality tradeoff. Measure CPU savings before choosing it.

### P2: Model-cache regression test no longer compiles; new path untested

tests/test_wii_alias_cache.py fails to compile the current extracted renderer:
Hyena_UploadStaticWorldBuffer is missing from its host stubs. Its stub also
forces Hyena_StaticVertexBudget() to zero, while the current Wii backend returns
2 MiB. It cannot validate the new nonzero-budget static-pose/VBO path, even
after merely adding the missing stub. Assertions still assume old object/key
limits and require review against the new intended behavior.

Action: cover real source with budget enabled and disabled, VBO upload failure,
pose and topology lifetime, memory limits, zombie body/limb/full-model mixing,
model-cache relocation and teardown. A successful cross-build is not this test.

### P2: Runtime logging discards messages rather than merely buffering them

source/platform/wii/boot_wii.c:28-33 writes runtime messages to the file only
when prefixed PERF or WII PERF. Other messages are never retained for a later
flush. Wii_BootSetRuntime(0) cannot recover discarded messages. This loses
warnings and diagnostic context that the report says should be buffered.

The online logger in engine/client/wii_online_platform.c:186-204 keeps a FILE
open but still calls synchronous fwrite and a periodic synchronous fflush.
Buffering reduces calls; it does not eliminate FAT stalls. The one-second
flush is checked only when another message is logged, not by an independent
timer, and the code ignores write/flush errors.

Action: use a bounded memory log/ring buffer if nonblocking runtime logging is
required, with an explicit overflow policy and flush/error handling. Measure
actual write durations before assigning them a 10-100 ms cost on this setup.

### P2: Binding swap does not guarantee every action stays bound

source/menu/menu_bindings.c:69-80 only restores the displaced command if the
action being assigned previously had a binding (old_key != -1). If that action
was already UNBOUND, assigning an occupied button still removes the previous
action's only binding. The displaced command is also truncated to 63 bytes.
Hold/double-tap assignments are not swapped with the normal assignment.

source/keys.c marks archive_revision dirty for normal bindings only; the
Key_SetHoldBinding and Key_SetDTBinding functions still do not do so. Claims
about autosaving every form of binding change are broader than implementation.

Action: specify conflict behavior, handle an initially unbound action explicitly,
preserve complete commands, and test compound normal/hold/double-tap layouts.

### P2: SDL filtering disables USB keyboard/mouse input as well as duplicates

source/platform/sdl/sys_sdl.c:316-329 drains and discards every SDL event other
than QUIT on Wii. Native Wii_PollInput reads WPAD/PAD, not USB keyboard events.
This prevents duplicate controller/IR events, but also removes legitimate SDL
keyboard/mouse input and cannot be called a behavior-preserving filter.

Action: filter by event/device source, or deliberately document the unsupported
devices rather than claim every discarded event was a duplicate.

## Networking changes requiring further validation

- CL_CheckDLFile in CL_RequestNextDownload corrects the package/ + FS_ROOT
  existence lookup. This is a sensible fix. Existence still does not itself
  prove the package's pure checksum, correct mounting or completed signon.
- Removing the SCTP return after ReadGamePacket is supported by the fact that
  SCTP_Decode first copies the complete datagram into stack storage. Advancing
  through remaining chunks does not rely on the overwritten net_message bytes.
  Callback/session lifetime still deserves an integration test. Do not reject
  this change merely because it removed a defensive-looking return.
- SACK length/gap endian conversion and delayed-ACK machinery already exist in
  the baseline reviewed here. Reports claiming there is no single-packet ACK
  timer do not describe this current source.
- DTLS transmit now handles flushing an old packet followed by a new one when
  the flush succeeds. If the old ssl_write is still WANT_WRITE, the new input
  is still not stored. SCTP has already allocated its TSN. This is not a general
  outgoing queue solution, and must be tested under repeated backpressure.
- cl_main.c:972 sets a 1200-byte game-layer MTU, while
  wii_online_dtls_mbedtls.c:233 sets the DTLS datagram MTU to 1200. SCTP adds its
  own header and DATA chunk before DTLS. A game payload around 1200 cannot fit
  that DTLS limit; transmit checks max_out_record_payload and can return MTU.
  Netchan does have adaptive MTU handling, so this alone is not proof of a
  permanent connection failure. A shared layered size budget and boundary
  tests are needed; the stated approximately 1293-byte packet is not what a
  DTLS context capped at 1200 will successfully emit.
- r18az retries all negative completion statuses, not only the reported -24.
  The local libogc-3.1.0 network_wii.c shows net_deinit closes the IP descriptor
  and waits for an in-flight init to stop; it is not a full reset of the Wi-Fi
  driver or IOS. A blocking deinit/IOS close plus the two-second sleep is not
  governed by the outer elapsed-time check. The advertised 45 seconds is not a
  strict wall-clock bound for every call in this sequence. Do not infer a fix
  for link association without a new Wii log and the exact IOS callback result.

## Changes with sound direction, without a measured FPS guarantee

- The original r27 IN_Init bug is real: platform init was gated on a connection
  flag set only by later input polling. The new IN_PlatformHasGamepad returning
  true makes registration reachable at startup. Setting .value manually alone
  would not have registered the command/cvar. This was an error in the previous
  implementation, not an invented finding in the supplied audit.
- Exact command matching fixes impulse-prefix collisions. Explicit cancellation
  of binding capture is useful. Native input device selection addresses the
  active-device filter responsible for some false UNBOUND displays.
- Limb-local currententity/interpolation state avoids using the body as the
  limb model key. Command-based topology lookup addresses body/full-model
  collisions. Cache validity when movable model allocations change still needs
  coverage; model data lives in a relocatable Quake cache.
- Contiguous indexed decal batching preserves order across texture changes and
  removes repeated submissions. It is separate from the quality-reducing cap.
- Enabling single-pass fog, persistent TEV state and static model VBOs can save
  work but need image comparisons, GL-state transition tests and memory checks.
  Hyena_CreateBuffer retains a CPU copy as well as the uploaded GPU buffer.
  A 2 MiB pose budget therefore is not a 2 MiB total allocation limit; additional
  UV/index/topology caches and the eight-slot CPU pose cache add further memory.
- Waypoint caching avoids some repeated ground traces, but PathfindPrepareGeometry
  itself scans edicts and waypoints. Follow-path cache invalidation must observe
  moving BSP obstacles; the current revision check is not a per-frame observer.
  Net FPS benefit for NDU/Warehouse cannot be deduced from these edits alone.

## Repair and verification order

1. Correct reliable retransmission semantics and ineffective image-OOM recovery;
   add lost-ACK/backpressure tests before another online candidate.
2. Fix lighting-hash UB; restore exact animation/effects for a quality-preserving
   default. Define cache lifetime and test the actual enabled VBO path.
3. Repair regression tests, logging retention, binding conflicts and dirty-state
   tracking; give changed binaries unique revisions and matching ELF/hash receipts.
4. Establish one reproducible PC reference session and a staged Wii signon trace
   with bounded, low-overhead diagnostics and verified package mounting.
5. Profile the same camera locations on NDU and Warehouse, recording CPU phase
   times, draw counts, cache hits, lightmap bytes and present/GPU waits separately.
   Optimize the measured dominant phase; do not infer it from aggregate FPS.
